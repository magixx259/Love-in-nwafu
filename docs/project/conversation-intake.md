# 对话资料如何归档

用户可以直接在对话框发送人物设定、校园故事、美术参考和修改意见，无需使用特定格式。

## 归档规则

1. 根据涉及对象分配到人物卡、外观设定、个人故事线、主线场景或校园资料。
2. 明确由用户指定的内容标为「已确认」，制作方提出的补充标为「提案」，尚未说明的部分保留「待定」。不擅自给女主增加性格、年龄、亲属关系或恋爱经历。
3. 同一人物始终使用固定编号。用户改昵称时更新显示名，不随意改动资源路径。
4. 有真实身份、照片、房间号等私人细节的原始资料保留在 `private/`；进入公开设定时使用化名或泛化地点。
5. 修改旧设定时更新对应主文件，并在文件末尾写一条简短变更记录；不在多份表格中各维护一套性格或外观。
6. 校园事实、课程知识和虚构剧情分开记录；事实需要来源，用户经历可作故事依据但不推定为全校通用情况。
7. 不替用户自动移动外部参考目录中的文件。`E:\lookdata` 目前作为外部参考入口，用户指定具体片段后再提取有用观察。

## 对话示例

- 「西西是……，平时说话……」→ `characters/ch02_xixi/profile.md`。
- 「俞菲姐的头发、衣服想这样……」→ `characters/ch01_yufei/appearance.md`。
- 「我想农农的个人线发生在……」→ `characters/ch03_nongnong/route.md`。
- 「报名之后真实发生过这件事……」→ 原始记录留私人目录，改编稿进入 `story/`。
- 「这张图用作动医楼参考」→ 原图与出处先放 `private/references/`，地点依据记入 `world/locations/`。

公开仓库的更新只包含适合公开的设定、文档和明确可分发的资源；私人原始记录不通过普通 Git 提交上传。
