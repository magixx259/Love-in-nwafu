# 防跑偏检查表

用户 2026-11-04：「我怕他们跑偏了」。这份文件就是用来防这件事的。
维护方：程序。每次合并前按第 2 节过一遍，结果记在 `handoff-log.md`。

## 1. 三道防线

**第一道：事前给锚点。** 每一路开工前必须先读 [current-scope.md](current-scope.md)——它是唯一的"事实来源"。设定只在这里改，别处只能引用。三句话记住边界：

- 策划：只改 `characters/` `story/` `world/` `docs/day01/`，**不碰 `game/`**。
- 美术：只在 `E:\ipplay` 和自己的 `assets/` 子目录里做，**不碰 `game/`**。
- 程序：只改 `game/` 与 `docs/project/` 里的技术文件，**不改定案人设和剧情走向**。

**第二道：事中小样本。** 每一路的第一件交付物必须是**一个样本**，不是一整批：策划先交一个场景、美术先交一张图、程序先交一个界面。样本对齐了再批量，跑偏的代价就只有一张图。

**第三道：事后体检。** 每次合并前按下面清单检查；发现偏离立刻停，不进 `main`。

## 2. 合并前检查清单

- [ ] 这次改动属于"大体"还是"细节"？属于大体 → 看板必须是 `已批准`，并注明用户批准的时间和原话。
- [ ] 有没有改 `current-scope.md` 里的定案条目？（改了就一定是大体，必须批）
- [ ] 剧本里的称呼、性格、关系，跟 `characters/*/profile.md` 一致吗？
- [ ] 有没有新增角色、新增结局、新增设定？（三者都算大体）
- [ ] 美术有没有换掉**已认可版本**？版本号变大不算批准。
- [ ] 新增素材有没有许可记录？没有就只标记为占位，不进正式版。
- [ ] 文本里有没有「·」（U+00B7）？有就换成「・」。
- [ ] lint 过了吗？启动有没有 `errors.txt`？有人实际点过吗？
- [ ] `git diff --cached --stat` 里有没有不属于本次范围的文件？（整目录 add 的老问题）

## 3. 偏航的早期信号

出现下面任何一条，先停下来问，不要继续做：

- 交付里出现了"我顺手加了一个角色/一段剧情/一个系统"。
- 剧本开始解释设定（"其实她是……"），而 `current-scope.md` 里没有。
- 美术开始换风格，理由是"这个更好看"。
- 有人在改 `game/` 但没说，或者文件时间对不上。
- 看板上出现连续几天同一状态没有变化（卡住了，不是没跑偏）。

## 4. 真的跑偏了怎么办

1. 立刻在 `handoff-log.md` 记一行，状态 `冲突待定`，写清哪个文件、哪里偏了。
2. 不进 `main`。已经进去了就用 `git revert <hash>` 回滚，**不要手改补救**。
3. 回到 `current-scope.md` 对一遍，确认哪个才是对的，再决定是改文档还是改内容。
4. 如果是设定本身就有歧义，那是我写文档没写清——由策划补一句定案，用户拍板。

## 5. 不变的一条

**这套检查不是用来卡人的。** 具体对白怎么写、代码怎么实现、图片怎么画，随便发挥；只有"往哪个方向走"和"长什么样"要用户拍板。
